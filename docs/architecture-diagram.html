Conversational Flow

  1. User types/speaks → Widget emits ↑
  2. Engine builds context (snapshot + catalog)
  3. Engine invokes agent with MCP tools
  4. Agent responds: message + widgets + layout
  5. Engine applies → writes new store
  6. Renderer reads store → maps components ↓
  7. Widgets re-render

Agent receives everything from Engine. Never reads store or descriptors.

Mechanical Flow

  1. User clicks → Widget emits action ↑
  2. Engine reads descriptor → mechanical
  3. Applies config change → calls service
  4. Receives data → writes store
  5. Renderer reads store → maps components ↓
  6. Widgets update

No agent involved. Engine writes, Renderer reads. Instant.

Semantic Flow

  1. Widget emits semantic action ↑
  2. Engine reads descriptor → semantic
  3. Same flow as conversational (2-7)

Descriptor classifies. Engine decides whether to invoke agent.

Descriptor: the core abstraction

One descriptor + one component per widget. Feeds two direct consumers: Engine (data_source, events, reducers, spawn_actions, agent_view) and Renderer (component). The agent never reads descriptors — it receives the catalog assembled by the Engine.

Engine: the only writer

The Engine is the only module that writes to the store. The agent proposes, services return data — the Engine applies everything. The Renderer only reads and reacts.

Agent: knows nothing about the system

Doesn't know about the Store or Descriptors. Gets everything from the Engine as parameters: snapshot, catalog, conversation, tools. Responds with a UI declaration.

Persistence

Dual mode: in-memory (GenServer with undo history) + optional PostgreSQL. Guest users identified by UUID cookie. Store serialized as JSONB. Async background persist — never blocks the UI.
